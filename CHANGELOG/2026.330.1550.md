# 2026.330.1550 — chore(pixi): pin v0.84.2, the current release

## Summary

Pin pixi to **v0.84.2** (the current release) instead of v0.70.2, in the one place it is declared
(`PIXI_VERSION`) and the two assertions/docs that name it.

Why: v0.70.2 is five minor releases behind, the release assets for both arches exist and were verified
(`pixi-{x86_64,aarch64}-unknown-linux-musl.tar.gz` → HTTP 200), and the environment fix that unblocks the
ComfyUI image build (opencharly/pod-comfyui#49) was re-tested against 0.84.2:

```
$ /tmp/pixi0842 install --frozen     # pod-comfyui's pixi.toml ([system-requirements] libc=2.39) + its re-locked lock
✔ The default environment has been installed.
```

That test also answers the question behind the bump: **the `[system-requirements] libc = 2.39` section is
still necessary on the latest pixi.** A builder appends it when a candy's `pixi.toml` lacks it, which makes
pixi resolve `linux-64-glibc-2-39`; a lock resolved for a bare `linux-64` fails `--frozen`. The candy must
declare the section (so the append is a no-op) and lock for that platform.
